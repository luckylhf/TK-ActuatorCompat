# Inspire 夹爪完整测试手册

适用版本：TG2.0-Pro v2.0.7.3、`inspire_gripper_full` v0.1.4。

本文只用于软件已经安装、编译、配置并重启后的夹爪验收。按照章节顺序执行，不要跳过启动检查、只读检查和测试后恢复。

## 1. 安全要求

- 测试前确认实际安装的末端与 YAML 配置一致。
- 夹爪运动范围内不得有人手、线缆、工具或硬物。
- 基础运动先使用 `velocity: [0.1]`、`effort: [0.1]`。
- 夹持测试只能使用海绵等安全、柔软且不会损坏夹爪的物体。
- 不得通过堵转、过温、过流或带电拔插设备来制造故障。
- 如果机器人指示灯变红、BodyControl 容器退出、夹爪异常运动或反馈中断，立即停止后续运动测试。

## 2. 确认配置和启动状态

### 2.1 查看启用的夹爪侧

```bash
GRIPPER_CONFIG=/home/ubuntu/ros2ws/install/body_control/share/body_control/param/inspire_gripper.yaml

grep -nE \
'^(left|right)_gripper_installed:' \
"$GRIPPER_CONFIG"
```

可能结果：

| 配置 | 实际模式 |
|---|---|
| 左 `true`，右 `true` | 左右双夹爪 |
| 左 `true`，右 `false` | 仅左夹爪，右侧通常为灵巧手 |
| 左 `false`，右 `true` | 仅右夹爪，左侧通常为灵巧手 |
| 左 `false`，右 `false` | 没有启用夹爪，不执行本文后续测试 |

只测试值为 `true` 且确实安装了夹爪的一侧。

### 2.2 检查 BodyControl 进程

先按遥控器 A 启动 BodyControl，然后执行：

```bash
PID=$(pgrep -f \
'component_container.*bodyctrl_nodes' |
head -1)

echo "BODYCTRL_PID=$PID"
```

预期：`BODYCTRL_PID` 后面是非空数字。如果为空，不执行运动测试。

### 2.3 检查加载的动态库

```bash
sudo grep -E \
'libbodyctrl_component|libinspire_gripper_full' \
/proc/$PID/maps
```

预期同时看到：

```text
lib/libbodyctrl_component.so
gripper_full/node/libinspire_gripper_full.so
```

### 2.4 检查 ROS 2 节点

```bash
ros2 node list |
grep -E \
'^/bodyctrl$|^/bodyctrl_nodes$|^/inspire_gripper_full$'
```

至少启用一侧夹爪时，预期看到：

```text
/bodyctrl
/bodyctrl_nodes
/inspire_gripper_full
```

如果缺少 `/inspire_gripper_full`，不执行运动测试。

## 3. 检查全部 ROS 2 接口

### 3.1 列出夹爪话题

```bash
ros2 topic list |
grep '^/inspire_gripper/' |
sort
```

双夹爪模式预期有 11 个话题：

```text
/inspire_gripper/clear_error_command
/inspire_gripper/fast_stop_command
/inspire_gripper/left_command
/inspire_gripper/left_error
/inspire_gripper/left_status
/inspire_gripper/right_command
/inspire_gripper/right_error
/inspire_gripper/right_status
/inspire_gripper/set_catch_mode_command
/inspire_gripper/set_max_openlen_command
/inspire_gripper/set_min_openlen_command
```

单夹爪模式预期有 8 个话题：5 个公共控制话题，加上实际夹爪侧的 command、status、error。未启用侧的三个话题必须不存在。

### 3.2 检查公共控制接口

```bash
ros2 topic info -v \
/inspire_gripper/clear_error_command

ros2 topic info -v \
/inspire_gripper/set_catch_mode_command

ros2 topic info -v \
/inspire_gripper/fast_stop_command

ros2 topic info -v \
/inspire_gripper/set_max_openlen_command

ros2 topic info -v \
/inspire_gripper/set_min_openlen_command
```

预期：

- `clear_error_command` 类型为 `std_msgs/msg/String`；
- 其余四个类型为 `bodyctrl_msgs/msg/CmdSetParam`；
- 每个话题都有 1 个订阅者，节点名为 `inspire_gripper_full`。

## 5. 单侧接口和只读反馈测试

### 5.1 检查运动指令订阅

```bash
ros2 topic info -v \
"/inspire_gripper/${SIDE}_command"
```

预期：

- 类型为 `sensor_msgs/msg/JointState`；
- `Subscription count: 1`；
- 订阅节点为 `inspire_gripper_full`。

### 5.2 检查反馈发布端

```bash
ros2 topic info -v \
"/inspire_gripper/${SIDE}_status"

ros2 topic info -v \
"/inspire_gripper/${SIDE}_error"
```

预期：

- status 类型为 `sensor_msgs/msg/JointState`；
- error 类型为 `std_msgs/msg/UInt32`；
- 两个话题各有 1 个发布者。

### 5.3 读取一次状态和错误码

```bash
timeout 5s ros2 topic echo --once \
"/inspire_gripper/${SIDE}_status"

timeout 5s ros2 topic echo --once \
"/inspire_gripper/${SIDE}_error"
```

预期两条命令都在 5 秒内返回。

status 字段含义：

| 字段 | 含义 |
|---|---|
| `name` | 左侧为 `inspire_gripper_left`，右侧为 `inspire_gripper_right` |
| `position` | 闭合百分比；完全打开约为 0，完全闭合约为 100 |
| `velocity` | 当前版本固定上报 0，不能用它测量实际运动速度 |
| `effort` | 夹爪返回的力反馈值，会随机械状态和负载变化，不要求严格位于 0～100 |

### 5.4 检查反馈频率

```bash
timeout 10s ros2 topic hz \
"/inspire_gripper/${SIDE}_status"
```

预期：

- 单夹爪模式单侧理论约 25 Hz；
- 双夹爪模式单侧理论约 12.5 Hz；
- 以持续稳定收到消息为主要通过条件。

## 6. 基础位置、速度和力度测试

运动指令的三个输入范围均为 0～1：

| 字段 | 0 | 1 |
|---|---|---|
| `position` | 完全打开 | 完全闭合 |
| `velocity` | 最低速度 | 最高速度 |
| `effort` | 最低力度 | 最高力度 |

当前节点根据 topic 决定控制左夹还是右夹；`name` 用于保持消息含义清晰。`header` 可以省略，省略时 ROS 2 自动使用默认空 Header。

### 6.1 低速、低力度完全打开

```bash
ros2 topic pub --once \
"/inspire_gripper/${SIDE}_command" \
sensor_msgs/msg/JointState \
"{name: ['${JOINT_NAME}'], position: [0.0], velocity: [0.1], effort: [0.1]}"

sleep 3

timeout 5s ros2 topic echo --once \
"/inspire_gripper/${SIDE}_status"

timeout 5s ros2 topic echo --once \
"/inspire_gripper/${SIDE}_error"
```

预期：

- 夹爪打开；
- `position` 接近 0，允许存在机械和标定误差；
- 完全打开停止后，error 通常为 `data: 1`。

### 6.2 移动到约 50% 位置

```bash
ros2 topic pub --once \
"/inspire_gripper/${SIDE}_command" \
sensor_msgs/msg/JointState \
"{name: ['${JOINT_NAME}'], position: [0.5], velocity: [0.1], effort: [0.1]}"

sleep 3

timeout 5s ros2 topic echo --once \
"/inspire_gripper/${SIDE}_status"
```

预期：夹爪停在中间附近，`position` 接近 50。实际值允许存在机械和标定误差。

### 6.3 低速、低力度完全闭合

空载执行，不要在夹爪中放硬物：

```bash
ros2 topic pub --once \
"/inspire_gripper/${SIDE}_command" \
sensor_msgs/msg/JointState \
"{name: ['${JOINT_NAME}'], position: [1.0], velocity: [0.1], effort: [0.1]}"

sleep 3

timeout 5s ros2 topic echo --once \
"/inspire_gripper/${SIDE}_status"

timeout 5s ros2 topic echo --once \
"/inspire_gripper/${SIDE}_error"
```

预期：

- 夹爪闭合；
- `position` 明显增大并接近 100；
- 空载闭合到最小位置通常为 `data: 2`；
- 如果夹到物体停止，可能为 `data: 6`。

### 6.4 速度参数对比

先以速度 0.1 打开：

```bash
ros2 topic pub --once \
"/inspire_gripper/${SIDE}_command" \
sensor_msgs/msg/JointState \
"{name: ['${JOINT_NAME}'], position: [0.0], velocity: [0.1], effort: [0.1]}"
```

动作完成后，以速度 0.3 闭合：

```bash
ros2 topic pub --once \
"/inspire_gripper/${SIDE}_command" \
sensor_msgs/msg/JointState \
"{name: ['${JOINT_NAME}'], position: [1.0], velocity: [0.3], effort: [0.1]}"
```

预期：速度 0.3 的动作明显快于速度 0.1。status 中的 `velocity` 仍固定为 0，因此以动作时间和肉眼观察判断。

### 6.5 力度参数对比

该项只允许夹取安全、柔软的测试物体。先打开夹爪并放入柔软物体：

```bash
ros2 topic pub --once \
"/inspire_gripper/${SIDE}_command" \
sensor_msgs/msg/JointState \
"{name: ['${JOINT_NAME}'], position: [0.0], velocity: [0.1], effort: [0.1]}"
```

使用低力度夹取：

```bash
ros2 topic pub --once \
"/inspire_gripper/${SIDE}_command" \
sensor_msgs/msg/JointState \
"{name: ['${JOINT_NAME}'], position: [1.0], velocity: [0.1], effort: [0.1]}"

sleep 3

timeout 5s ros2 topic echo --once \
"/inspire_gripper/${SIDE}_status"
```

预期：夹爪夹到物体后停止，运行状态可能为 `data: 6`。`effort` 反馈随负载变化，但不要求与命令中的 0.1 数值相等。

力度 0.3 只在确认物体和夹爪安全后测试：

```bash
ros2 topic pub --once \
"/inspire_gripper/${SIDE}_command" \
sensor_msgs/msg/JointState \
"{name: ['${JOINT_NAME}'], position: [1.0], velocity: [0.1], effort: [0.3]}"
```

预期：允许夹持力表现与 0.1 不同；不以 status 的 `effort` 精确比例作为通过条件。

```bash
"{cmds: [{name: ${DEVICE_ID}, param: 0.0}]}"
```

预期：设置命令本身不产生运动。

```bash
ros2 topic pub --once \
```

## 9. 最大物理开度限制

该参数使用 0～100 的物理开度百分比，与运动命令的闭合方向相反。

先把最大物理开度临时设为 80%：

```bash
ros2 topic pub --once \
/inspire_gripper/set_max_openlen_command \
bodyctrl_msgs/msg/CmdSetParam \
"{cmds: [{name: ${DEVICE_ID}, param: 80.0}]}"
```

发送完全打开命令：

```bash
ros2 topic pub --once \
"/inspire_gripper/${SIDE}_command" \
sensor_msgs/msg/JointState \
"{name: ['${JOINT_NAME}'], position: [0.0], velocity: [0.1], effort: [0.1]}"

sleep 3

timeout 5s ros2 topic echo --once \
"/inspire_gripper/${SIDE}_status"
```

预期：夹爪不能开到原来的最大位置；status 使用闭合百分比，所以 `position` 预计在约 20，而不是约 0。

立即恢复最大物理开度为 100%：

```bash
ros2 topic pub --once \
/inspire_gripper/set_max_openlen_command \
bodyctrl_msgs/msg/CmdSetParam \
"{cmds: [{name: ${DEVICE_ID}, param: 100.0}]}"
```

再次完全打开并检查：

```bash
ros2 topic pub --once \
"/inspire_gripper/${SIDE}_command" \
sensor_msgs/msg/JointState \
"{name: ['${JOINT_NAME}'], position: [0.0], velocity: [0.1], effort: [0.1]}"

sleep 3

timeout 5s ros2 topic echo --once \
"/inspire_gripper/${SIDE}_status"
```

预期：恢复完整打开行程，`position` 回到约 0。

## 11. 快速停止和恢复

先完全打开：

```bash
ros2 topic pub --once \
"/inspire_gripper/${SIDE}_command" \
sensor_msgs/msg/JointState \
"{name: ['${JOINT_NAME}'], position: [0.0], velocity: [0.1], effort: [0.1]}"

sleep 3
```

低速闭合，并在运动中发送快速停止：

```bash
ros2 topic pub --once \
"/inspire_gripper/${SIDE}_command" \
sensor_msgs/msg/JointState \
"{name: ['${JOINT_NAME}'], position: [1.0], velocity: [0.05], effort: [0.1]}"

sleep 0.3

ros2 topic pub --once \
/inspire_gripper/fast_stop_command \
bodyctrl_msgs/msg/CmdSetParam \
"{cmds: [{name: ${DEVICE_ID}, param: 1.0}]}"
```

查看反馈：

```bash
timeout 5s ros2 topic echo --once \
"/inspire_gripper/${SIDE}_status"

timeout 5s ros2 topic echo --once \
"/inspire_gripper/${SIDE}_error"
```

预期：夹爪在行程中停止，`position` 停在中间位置；运行状态通常为 `data: 3`。以夹爪实际停止且反馈没有中断作为主要判断。

解除快速停止：

```bash
ros2 topic pub --once \
/inspire_gripper/fast_stop_command \
bodyctrl_msgs/msg/CmdSetParam \
"{cmds: [{name: ${DEVICE_ID}, param: 0.0}]}"
```

清错并重新打开：

```bash
ros2 topic pub --once \
/inspire_gripper/clear_error_command \
std_msgs/msg/String \
"{data: '${SIDE}'}"

ros2 topic pub --once \
"/inspire_gripper/${SIDE}_command" \
sensor_msgs/msg/JointState \
"{name: ['${JOINT_NAME}'], position: [0.0], velocity: [0.1], effort: [0.1]}"

sleep 3

timeout 5s ros2 topic echo --once \
"/inspire_gripper/${SIDE}_error"
```

预期：夹爪恢复运动并完全打开，error 通常为 `data: 1`。

## 12. 清除错误接口

单独清除当前测试侧：

```bash
ros2 topic pub --once \
/inspire_gripper/clear_error_command \
std_msgs/msg/String \
"{data: '${SIDE}'}"
```

同时请求清除全部已启用夹爪：

```bash
ros2 topic pub --once \
/inspire_gripper/clear_error_command \
std_msgs/msg/String \
"{data: 'all'}"
```

预期：清错命令本身不产生夹爪运动，BodyControl 和 `/inspire_gripper_full` 继续运行。只有配置为已安装的夹爪侧会收到清错请求。

## 13. 状态与故障码判读

读取当前测试侧：

```bash
timeout 5s ros2 topic echo --once \
"/inspire_gripper/${SIDE}_error"
```

虽然 topic 名称包含 `error`，无故障时发布的是运行状态；检测到设备错误位时才发布 11～16。

| `data` | 含义 | 处理 |
|---:|---|---|
| 0 | 无错误或没有有效运行状态 | 结合 status 和后续消息判断 |
| 1 | 张开到最大并停止 | 正常打开终态 |
| 2 | 闭合到最小并停止 | 正常闭合终态 |
| 3 | 已停止 | 快速停止后可能出现 |
| 4 | 正在夹取 | 正常运动状态 |
| 5 | 正在张开 | 正常运动状态 |
| 6 | 夹到物体并停止 | 正常夹持终态 |
| 11 | 堵转故障 | 停止测试，排除机械阻挡后清错 |
| 12 | 过温故障 | 停止测试并等待温度下降，不立即反复清错 |
| 13 | 过流故障 | 停止测试，检查负载和机械阻挡后清错 |
| 14 | 内部通信故障 | 停止测试，检查设备通信 |
| 15 | 未知设备故障 | 停止测试，保留现场信息并排查设备 |
| 16 | 未识别的错误位 | 停止测试，保留现场信息并排查协议返回 |
| 33072 | 超过 2 秒没有收到该设备的有效响应 | 检查夹爪供电、CAN 接线、设备 ID 和通道 |

正常全开和全闭不应该固定显示为 `11/12`。如果出现 11～16 或 33072，不继续发送运动命令。

## 14. 双夹爪第二侧测试

如果左右两侧都是夹爪，在一侧完成第 4～13 节后，重新设置变量：

测试左侧：

```bash
SIDE=left
DEVICE_ID=18
JOINT_NAME=inspire_gripper_left
```

测试右侧：

```bash
SIDE=right
DEVICE_ID=28
JOINT_NAME=inspire_gripper_right
```
